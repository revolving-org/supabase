## Body
### Summary

This PR makes the self-hosted Supavisor pooler respect the `POSTGRES_HOST` environment variable when seeding its tenant configuration, instead of always hard-coding `db` as the database host.

In the default Docker setup, Postgres runs as the `db` service and this continues to work unchanged. But when users point Supabase at an external Postgres instance via `POSTGRES_HOST`, Supavisor will now connect to that host instead of still trying to reach `db:PORT`.
